# AGENTS.md

Self-hosted software factory PoC: a Forgejo issue with the `factory` label triggers a webhook, an agent runs in a sandbox, and its patch becomes a PR. Simple solutions win; "does not work" is a valid test result.

## Environment

- Homelab for testing, behind VPN. No production, no real users or customer data. Break things that are yours; plain HTTP and LAN-bound services are fine. Do not open it to the internet (port forwards, public tunnels).
- Sandboxes and microVMs (Docker, gVisor, Firecracker, libkrun, nested VMs) can be run without asking. The VPN limits who reaches the host, not what a sandbox reaches, so isolation and egress results are real findings.
- Linux with Docker (`runc` and `runsc`) and nested `/dev/kvm`. RAM is shared: check `sudo -n docker ps` before a heavy test.

## Layout

| Path | Purpose |
| --- | --- |
| `up.sh` | Starts base services; generates `litellm/.env` on first run |
| `forgejo/` | Git and issues, `:3000` |
| `litellm/` | LLM proxy, `:4000` |
| `gateway/` | `factory-llm-gw` (nginx, maps source IP to key) and `factory-pkg-gw` (squid, `allowlist.txt`) |
| `orchestrator/` | `factory.ts` (webhook to PR), `yfactory.ts` + `ui/`, `adapters/` (one per runtime), `sandbox-image/` |
| `fixture/` | Test repo code and a 15-service Compose stack |
| `tests/` | `e2e.sh`, `security.ts <runtime>`, results in `tests/results/` |
| `runtimes/` | One directory per runtime still in evaluation (Microsandbox, sbx, E2B); notes on dropped ones are in `../research/runtimes-archive/` |

## Commands

```bash
./up.sh
sudo docker compose -f orchestrator/compose.yml up -d --build   # FACTORY_RUNTIME sets the runtime, default gvisor
tests/e2e.sh "Task title"                                       # needs the orchestrator running
sudo -E node tests/security.ts gvisor
```

## Rules

- **Secrets:** do not read or print `orchestrator/.env` or `litellm/.env`, and do not copy real keys into a sandbox. In tests use only `FAKE-SECRET-<runtime>-123`.
- **External accounts:** do not create accounts or sign in to external services. Record it as a finding if a runtime needs one.
- **Other people's resources:** prefix what you create with the runtime name, leave other containers and networks alone, no broad `pkill -f`. Clean up when done.
- **Downloads:** read install scripts before running them, keep downloads in their own empty directory.
- **Host-level changes** (`/etc/docker`, restarting Docker, host firewall): record the need as a finding or use a nested VM, unless the task explicitly asks for it.
- Report what you measured separately from what you only read; anything not run is "untested".
